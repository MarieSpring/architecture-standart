### <a name="_3bfxc9a45514"></a>**Функциональные требования**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
|1|Сотрудник кол-центра|Получение актуальных ставок|Сотрудник может просматривать актуальные депозитные ставки в системе кол-центра|
|2|Сотрудник партнёрского кол-центра|Передача информации об актуальных ставках депозитов|Партнёрский кол-центр получает файл с актуальными ставками через SFTP.|
### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
|1|Защита данных при передаче через SFTP с использованием шифрования|
|2|Повторная попытка отправки в случае ошибки передачи файла во внешний кол-центр|
|3|Данные должны передаваться ежедневно|

### <a name="_qmphm5d6rvi3"></a>**Решение**
Диаграммы контекста и контейнеров представлены в файле  [C4.drawio](C4.drawio)

Для партнёрского кол-центра передача ставок реализована через SFTP, так как они не поддерживают API-интеграцию.
Для снижения нагрузки на операторов и минимизации ошибок используется автоматизация обновления ставок.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
Использование API для партнёрского кол-центра – невозможно, партнёр не поддерживает API.
Ручная передача файлов ставок в кол-центр – задержка в передаче данных, риск ошибок.

**Недостатки, ограничения, риски**

Партнёрский кол-центр должен своевременно загружать и обрабатывать файлы с ставками.
Возможны задержки в обновлении ставок по причине зависимостей от внешних систем.

### **Список крупных задач**
1. Система кол-центра
-  Разработка функционала для загрузки и отображения актуальных ставок операторам.
- Добавить интеграцию с АБС управления ставками.

2. Партнёрский кол-центр
- Разработка функционала для отображения ставок в системе.
-  Настройка процесс приёма файлов через SFTP с актуальными ставками. 

3. АБС
- Реализовать API для получения актуальных ставок.
- Настроить автоматическое обновление ставок.
